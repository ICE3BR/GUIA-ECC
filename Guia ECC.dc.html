O que é o ECC

ECC não é um app separado, é um conjunto de agentes, skills, comandos, regras e hooks que roda dentro de harnesses como Claude Code, Codex, Cursor ou OpenCode. Em vez de reexplicar "planeje antes de codar" ou "escreva testes primeiro" em todo prompt, você instala isso uma vez e esses hábitos passam a fazer parte de como o agente trabalha.

→
2test
→
3implement
→
4review

5verify

6remember

Como começar em um projeto novo

Passo a passo resumido — a aba Config tem o detalhe completo por harness.

01
/plugin marketplace add https://github.com/affaan-m/ECC e /plugin install ecc@ecc Claude Code nativo Instala o plugin inteiro (68 agentes, 284 skills, 94 comandos). Uma vez por máquina/usuário, não por projeto. Confirme com /plugin list ecc@ecc.
02
Instalar as rules da sua stack (manual) ECC Plugins não distribuem rules/. Copie rules/common + a pasta da sua linguagem para ~/.claude/rules/ecc/.
03
/ecc:project-init ECC Detecta a stack do projeto e devolve um plano dry-run do que instalar/ativar: quais rules, skills e agentes combinam.
04
npx -y ecc-agentshield scan --path . ECC Baseline de segurança: segredos vazados, permissões abertas, risco em hooks e MCPs.

Config

Como instalar o ECC do zero em cada harness, e como configurar depois: rules, perfis de hooks, MCPs, memória e otimização de custo.

{{ h.label }}

Claude Code — caminho recomendado (plugin)

/plugin marketplace add https://github.com/affaan-m/ECC
/plugin install ecc@ecc

Instala skills, agents, commands e hooks de uma vez. Não rode depois um install manual completo por cima — misturar os dois caminhos duplica hooks/comandos.

Confirmar a instalação:

/plugin list ecc@ecc

Alternativa declarativa, direto no ~/.claude/settings.json:

{
  "extraKnownMarketplaces": {
    "ecc": { "source": { "source": "github", "repo": "affaan-m/ECC" } }
  },
  "enabledPlugins": { "ecc@ecc": true }
}

Requisito: Claude Code CLI v2.1.0 ou mais recente (claude --version). Versões antigas têm bug de "Duplicate hooks file detected".

Claude Code — caminho alternativo (instalação manual completa)

Só usar quando intencionalmente não for usar o caminho de plugin:

git clone https://github.com/affaan-m/ECC.git
cd ECC
./install.sh --profile full

Windows:

git clone https://github.com/affaan-m/ECC.git
cd ECC
.\install.ps1 --profile full

Se escolher esse caminho, não rode /plugin install depois. Perfis parciais: --profile minimal (sem hooks), --profile core (básico), ou seleção explícita:

./install.sh --target claude --skills tdd-workflow,security-review
node scripts/ecc.js consult "security reviews" --target claude

Codex (macOS app + CLI)

Caminho nativo (marketplace, ainda experimental):

codex plugin marketplace add affaan-m/ECC
codex plugin add ecc@ecc
codex plugin list --json
node scripts/codex/check-plugin-cache.js

Caminho de sync (mais confiável hoje, recomendado):

git clone https://github.com/affaan-m/ECC.git
cd ECC
npm install
bash scripts/sync-ecc-to-codex.sh

O script mescla os servidores MCP do ECC no ~/.codex/config.toml de forma add-only. Use --dry-run para simular, ou --update-mcp para atualizar.

Codex não tem hooks no mesmo nível do Claude Code; enforcement via AGENTS.md (raiz) + .codex/AGENTS.md (suplemento).

Cursor

./install.sh --profile minimal --target cursor typescript
./install.sh --profile minimal --target cursor python golang swift php

Windows:

.\install.ps1 --target cursor typescript

Traz 34 rules (9 comuns + 25 por linguagem), 48 agentes prefixados .cursor/agents/ecc-*.md, hooks adaptados (Cursor tem 20 tipos de evento contra 8 do Claude Code, via .cursor/hooks/adapter.js). Não instala AGENTS.md raiz dentro de .cursor/.

GitHub Copilot (VS Code)

Não precisa de instalação, os arquivos já vêm prontos no repositório: .github/copilot-instructions.md (instruções sempre carregadas) e .github/prompts/*.prompt.md (plan, tdd, security-review, build-fix, refactor). Basta abrir um repositório com esses arquivos e Copilot Chat ativo.

Sem hooks, sem agentes, sem delegação — Copilot não tem essas APIs.

Instalar as rules da sua stack

Plugins do Claude Code não trazem rules/. Copie manualmente rules/common (sempre) + a pasta da linguagem usada:

git clone https://github.com/affaan-m/ECC.git
cd ECC
mkdir -p ~/.claude/rules/ecc
cp -R rules/common ~/.claude/rules/ecc/
cp -R rules/python ~/.claude/rules/ecc/   # trocar pela sua stack

Disponíveis: common, typescript, python, golang, swift, php, arkts. Para rules por projeto, copie para .claude/rules/ecc/ dentro do repositório do projeto.

Descobrir o que instalar para um projeto específico

node scripts/ecc.js consult "security reviews" --target claude

Ou, dentro do Claude Code, o comando /ecc:project-init: detecta a stack e devolve plano dry-run cruzando com os manifests do ECC.

Gerenciador de pacotes (npm / pnpm / yarn / bun)

Detecção automática, em ordem: CLAUDE_PACKAGE_MANAGER, .claude/package-manager.json do projeto, campo packageManager do package.json, lockfile, config global, e por fim o primeiro disponível.

export CLAUDE_PACKAGE_MANAGER=pnpm
node scripts/setup-package-manager.js --global pnpm
node scripts/setup-package-manager.js --project bun
node scripts/setup-package-manager.js --detect

Ou use /setup-pm dentro do Claude Code.

Perfil de hooks e variáveis de ambiente

export ECC_HOOK_PROFILE=standard          # minimal | standard | strict
export ECC_DISABLED_HOOKS="pre:bash:tmux-reminder,post:edit:typecheck"
export ECC_SESSION_START_MAX_CHARS=4000    # padrão: 8000 caracteres
export ECC_SESSION_START_CONTEXT=off       # desliga contexto extra no início da sessão
export ECC_SESSION_RETENTION_DAYS=14       # padrão: 30 dias; 0/off/never mantém tudo
export ECC_MAX_INJECTED_INSTINCTS=6        # instincts aprendidos injetados por sessão
export ECC_INSTINCT_CONFIDENCE_THRESHOLD=0.7
export ECC_CONTEXT_MONITOR_COST_WARNINGS=off  # mantém avisos de contexto/loop, remove estimativa de custo

Windows PowerShell:

[Environment]::SetEnvironmentVariable('ECC_CONTEXT_MONITOR_COST_WARNINGS', 'off', 'User')
[Environment]::SetEnvironmentVariable('ECC_SESSION_RETENTION_DAYS', '14', 'User')

Isolamento de dados entre harnesses na mesma máquina:

export ECC_AGENT_DATA_HOME="$HOME/.cursor/ecc"   # Claude Code mantém o padrão ~/.claude

Configurar MCPs

Instalações via plugin não ativam automaticamente os servidores MCP do ECC. Use /mcp dentro do Claude Code para ativar/desativar em tempo real, ou copie entradas de mcp-configs/mcp-servers.json para um .mcp.json do projeto. O ECC empacota só um conector por padrão (chrome-devtools).

export ECC_DISABLED_MCPS="chrome-devtools"   # filtro usado só durante install/sync, não runtime

Regra geral: menos de 10 MCPs ativos e menos de 80 tools ativas por projeto.

Memory Vault (contexto entre sessões/harnesses)

Instalações via plugin não trazem o runtime da CLI de memória. Instalar uma vez, globalmente:

npm install -g ecc-universal
ecc memory init --scope project
ecc memory search "termo" --target-harness codex
ecc memory read <memory-id>
ecc memory doctor

Dentro do Claude Code, /ecc:unified-memory guia o mesmo fluxo. Memórias em Markdown em .ecc/memory/ (projeto) ou ~/.ecc/memory/ (usuário) — contexto não revisado, sempre verificar contra a fonte real.

Segurança: baseline com AgentShield

npx -y ecc-agentshield scan --path .        # varredura rápida
npx ecc-agentshield scan --fix              # corrige automaticamente o que for seguro
npx ecc-agentshield scan --opus --stream    # análise profunda (red team / blue team / auditor)
npx ecc-agentshield init                    # gera config segura do zero

Ou /security-scan dentro do Claude Code. Roda uma vez como baseline e de novo sempre que adicionar um MCP ou hook novo.

Reset, reparo e desinstalação

node scripts/ecc.js list-installed
node scripts/ecc.js doctor            # só detecta instalações via install.sh/ecc-universal
node scripts/ecc.js repair
node scripts/ecc.js uninstall --dry-run
node scripts/uninstall.js --dry-run   # caminho direto alternativo

Se instalado via plugin, use /plugin list ecc@ecc para verificar saúde, não node scripts/ecc.js doctor (só enxerga instalações manuais). Se ECC aparecer duplicado: remova o plugin, rode o uninstall dry-run, remova rules copiadas manualmente que não quiser mais, e reinstale usando um único caminho.

Por padrão, alguns harnesses do ECC instalam na pasta do usuário (~, vale pra toda sessão e todo projeto), e outros já instalam sempre dentro do projeto atual. Isso importa para quem já usa o ECC global num harness (ex: Claude Code) e quer testar outro harness ou uma configuração diferente sem arriscar bagunçar o que já funciona.

Isolar Claude Code por projeto

Duas situações diferentes, escolha uma:

a
Você já usa o plugin global e só quer rules específicas do projeto Caso mais comum. Seguro — rules não fazem parte do que o plugin distribui: 
cd meu-projeto
mkdir -p .claude/rules/ecc
cp -R /caminho/para/ECC/rules/common .claude/rules/ecc/
cp -R /caminho/para/ECC/rules/python .claude/rules/ecc/   # trocar pela stack do projeto
O Claude Code prioriza rules do projeto sobre rules globais quando ambas existem.
b
Você quer isolar o ECC inteiro (skills, agentes, comandos, rules) num projeto de teste Sem depender do plugin global. Use o alvo claude-project do instalador manual: 
cd meu-projeto-de-teste
git clone https://github.com/affaan-m/ECC.git /tmp/ecc-src
node /tmp/ecc-src/scripts/install-apply.js --target claude-project --profile core
Grava tudo em ./.claude/ (rules em rules/ecc, skills soltas em skills/), sem tocar em ~/.claude/. Atenção: não combine com o plugin ecc@ecc ativo no mesmo projeto — empilhar métodos de instalação duplica skills e comandos.

Testar Codex e OpenCode sem tocar na configuração global

Ambos suportam rodar "de dentro do próprio repositório", o que evita gravar em ~/:

# Codex: lê AGENTS.md e .codex/ automaticamente, sem sync para ~/.codex
cd ECC
codex

# OpenCode: lê .opencode/opencode.json do próprio repositório
cd ECC
opencode

Útil para conhecer o comportamento do ECC nesses harnesses antes de decidir sincronizar para a configuração global (bash scripts/sync-ecc-to-codex.sh para Codex, ou copiar .opencode/ para um projeto próprio no caso do OpenCode).
